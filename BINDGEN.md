# Bindgen Documentation for Mozilla Authenticator-RS

## Overview

This document provides comprehensive instructions on how to use bindgen to add support for new architectures in the Mozilla Authenticator-RS library. The authenticator-rs library uses bindgen to generate Rust bindings for platform-specific ioctl constants required for HID (Human Interface Device) communication on Linux systems.

## Prerequisites

### Required Tools

Before working with bindgen in this project, ensure you have the following installed:

```bash
# Install Rust and Cargo (if not already installed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Install bindgen (automatically handled by Cargo when using the feature)
# The bindgen dependency is specified in Cargo.toml under [build-dependencies]

# Install system dependencies (Linux)
sudo apt-get update
sudo apt-get install build-essential clang libclang-dev

# For other distributions:
# Fedora/RHEL: sudo dnf install gcc clang clang-devel
# Arch Linux: sudo pacman -S gcc clang
```

### System Headers

The bindgen process requires access to Linux system headers:

```bash
# Ubuntu/Debian
sudo apt-get install linux-libc-dev

# Fedora/RHEL
sudo dnf install kernel-headers glibc-devel

# Arch Linux
sudo pacman -S linux-api-headers
```

## Understanding the Current System

### Architecture Detection

The authenticator-rs library uses conditional compilation to select the appropriate ioctl constants for each architecture. The build system works as follows:

1. **Header File**: `src/transport/linux/hidwrapper.h` defines the constants that bindgen will extract
2. **Build Script**: `build.rs` uses bindgen to generate architecture-specific Rust code
3. **Output Files**: Generated `ioctl_{arch}.rs` files contain the platform-specific constants
4. **Integration**: The main code imports the appropriate constants based on the target architecture

### How Bindgen Works in This Context

```rust
// In build.rs
let bindings = bindgen::Builder::default()
    .header("src/transport/linux/hidwrapper.h")
    .allowlist_var("_HIDIOCGRDESCSIZE")
    .allowlist_var("_HIDIOCGRDESC")
    .generate()
    .expect("Unable to get hidraw bindings");
```

This process:
1. Reads the C header file `hidwrapper.h`
2. Extracts only the allowed variables (`_HIDIOCGRDESCSIZE` and `_HIDIOCGRDESC`)
3. Generates Rust constants with the correct values for the target architecture
4. Writes the output to an architecture-specific file

## Adding a New Architecture

### 1. Identify Your Architecture

First, determine your target architecture and endianness:

```bash
# Check current architecture
rustc --version --verbose | grep host

# Or use system commands
uname -m
lscpu | grep Architecture
```

### 2. Modify build.rs

Add your architecture to the conditional compilation chain in `build.rs`. Follow the existing pattern:

```rust
} else if cfg!(all(target_arch = "your_arch", target_endian = "your_endian")) {
    "ioctl_your_arch_your_endian.rs"
```

**Example for SPARC64 (as requested in issue #348):**

```rust
} else if cfg!(all(target_arch = "sparc64", target_endian = "big")) {
    "ioctl_sparc64be.rs"
```

### 3. Generate the Binding File

Run the binding generation process:

```bash
# Enable the binding-recompile feature to trigger code generation
cargo build --features binding-recompile

# Or for a specific target
cargo build --target sparc64-unknown-linux-gnu --features binding-recompile
```

### 4. Verify the Generated File

Check that the new ioctl file was created:

```bash
ls -la src/transport/linux/ioctl_*
```

The generated file should contain something like:

```rust
/* automatically generated by rust-bindgen */

pub type __u32 = ::std::os::raw::c_uint;
pub const _HIDIOCGRDESCSIZE: __u32 = [architecture-specific-value];
pub const _HIDIOCGRDESC: __u32 = [architecture-specific-value];
```

## Step-by-Step Tutorial

Let's walk through adding support for SPARC64 architecture:

### Step 1: Prepare Your Environment

```bash
# Clone the repository (if you haven't already)
git clone https://github.com/mozilla/authenticator-rs.git
cd authenticator-rs

# Ensure you have the SPARC64 target installed
rustup target add sparc64-unknown-linux-gnu

# Install cross-compilation tools if needed
sudo apt-get install gcc-sparc64-linux-gnu
```

### Step 2: Modify build.rs

Edit the `build.rs` file to add SPARC64 support:

```diff
    } else if cfg!(all(target_arch = "loongarch64", target_endian = "little")) {
        "ioctl_loongarch64.rs"
+   } else if cfg!(all(target_arch = "sparc64", target_endian = "big")) {
+       "ioctl_sparc64be.rs"
    } else {
        panic!("architecture not supported");
    };
```

### Step 3: Generate Bindings

```bash
# Set up cross-compilation environment
export CC_sparc64_unknown_linux_gnu=sparc64-linux-gnu-gcc
export AR_sparc64_unknown_linux_gnu=sparc64-linux-gnu-ar

# Generate the bindings for SPARC64
cargo build --target sparc64-unknown-linux-gnu --features binding-recompile
```

### Step 4: Verify and Test

```bash
# Check that the file was generated
ls -la src/transport/linux/ioctl_sparc64be.rs

# Verify the contents
cat src/transport/linux/ioctl_sparc64be.rs

# Test compilation without the recompile feature
cargo check --target sparc64-unknown-linux-gnu
```

### Step 5: Commit Your Changes

```bash
git add build.rs src/transport/linux/ioctl_sparc64be.rs
git commit -m "Add SPARC64 big-endian architecture support"
```

## Supported Architectures

The following architectures are currently supported:

### x86 Family
- **x86** (32-bit): `ioctl_x86.rs`
- **x86_64** (64-bit): `ioctl_x86_64.rs`

### ARM Family
- **ARM (little-endian)**: `ioctl_armle.rs`
- **ARM (big-endian)**: `ioctl_armbe.rs`
- **AArch64 (little-endian)**: `ioctl_aarch64le.rs`
- **AArch64 (big-endian)**: `ioctl_aarch64be.rs`

### MIPS Family
- **MIPS (big-endian)**: `ioctl_mipsbe.rs`
- **MIPS (little-endian)**: `ioctl_mipsle.rs`
- **MIPS64 (little-endian)**: `ioctl_mips64le.rs`

### PowerPC Family
- **PowerPC (little-endian)**: `ioctl_powerpcle.rs`
- **PowerPC (big-endian)**: `ioctl_powerpcbe.rs`
- **PowerPC64 (little-endian)**: `ioctl_powerpc64le.rs`
- **PowerPC64 (big-endian)**: `ioctl_powerpc64be.rs`

### Other Architectures
- **S390X (big-endian)**: `ioctl_s390xbe.rs`
- **RISC-V 64-bit (little-endian)**: `ioctl_riscv64.rs`
- **LoongArch64 (little-endian)**: `ioctl_loongarch64.rs`

### Architecture Naming Convention

The naming convention for ioctl files is:
```
ioctl_{architecture}{endianness}.rs
```

Where:
- `{architecture}` is the CPU architecture (x86, arm, mips, etc.)
- `{endianness}` is optional but included when the architecture supports both:
  - `le` for little-endian
  - `be` for big-endian
  - Omitted for architectures with only one common endianness

## Troubleshooting

### Common Issues and Solutions

#### Issue: "Unable to get hidraw bindings"

**Symptoms:**
```
error: Unable to get hidraw bindings
```

**Solutions:**
1. Install clang and libclang-dev:
   ```bash
   sudo apt-get install clang libclang-dev
   ```

2. Set the LIBCLANG_PATH environment variable:
   ```bash
   export LIBCLANG_PATH=/usr/lib/x86_64-linux-gnu
   cargo build --features binding-recompile
   ```

3. Install kernel headers:
   ```bash
   sudo apt-get install linux-libc-dev
   ```

#### Issue: "unresolved imports" Error

**Symptoms:**
```
error[E0432]: unresolved imports `super::hidwrapper::_HIDIOCGRDESC`, `super::hidwrapper::_HIDIOCGRDESCSIZE`
```

**Root Cause:**
The ioctl file for your architecture doesn't exist or wasn't generated properly.

**Solutions:**
1. Ensure the architecture is added to `build.rs`
2. Regenerate bindings with the correct target:
   ```bash
   cargo clean
   cargo build --target your-target-triple --features binding-recompile
   ```

3. Verify the generated file exists and has the correct constants

#### Issue: Cross-compilation Problems

**Symptoms:**
```
error: linking with `cc` failed
```

**Solutions:**
1. Install cross-compilation toolchain:
   ```bash
   # For ARM64
   sudo apt-get install gcc-aarch64-linux-gnu
   
   # For other architectures, replace aarch64 with your target
   ```

2. Set environment variables:
   ```bash
   export CC_aarch64_unknown_linux_gnu=aarch64-linux-gnu-gcc
   export AR_aarch64_unknown_linux_gnu=aarch64-linux-gnu-ar
   ```

#### Issue: Architecture Not Supported Panic

**Symptoms:**
```
thread 'main' panicked at 'architecture not supported'
```

**Solution:**
Add your architecture to the conditional compilation chain in `build.rs` following the pattern described above.

### Debugging Tips

1. **Verbose Output**: Use cargo with verbose flag to see detailed build information:
   ```bash
   cargo build --features binding-recompile --verbose
   ```

2. **Check Generated Constants**: Examine the generated ioctl file to ensure constants are reasonable:
   ```bash
   cat src/transport/linux/ioctl_your_arch.rs
   ```

3. **Compare with Existing**: Compare your generated constants with existing architectures to verify they make sense.

4. **Test Incrementally**: Build without features first, then add the binding-recompile feature:
   ```bash
   cargo check --target your-target
   cargo build --target your-target --features binding-recompile
   ```

## Advanced Usage

### Custom Bindgen Configuration

For special cases, you might need to customize the bindgen configuration. Edit the bindgen::Builder in `build.rs`:

```rust
let bindings = bindgen::Builder::default()
    .header("src/transport/linux/hidwrapper.h")
    .allowlist_var("_HIDIOCGRDESCSIZE")
    .allowlist_var("_HIDIOCGRDESC")
    // Add custom configurations here
    .clang_arg("-I/path/to/custom/headers")  // Custom include paths
    .ctypes_prefix("::std::os::raw")         // Customize type prefixes
    .generate()
    .expect("Unable to get hidraw bindings");
```

### Conditional Features

You can make architecture support conditional on certain features:

```rust
// In build.rs, wrap your architecture check:
#[cfg(feature = "experimental-architectures")]
} else if cfg!(all(target_arch = "experimental_arch", target_endian = "little")) {
    "ioctl_experimental_arch.rs"
```

Then in `Cargo.toml`:
```toml
[features]
experimental-architectures = []
```

### Multiple Header Files

If you need to process multiple header files for a new architecture:

```rust
let bindings = bindgen::Builder::default()
    .header("src/transport/linux/hidwrapper.h")
    .header("src/transport/linux/additional_headers.h")  // Additional headers
    .allowlist_var("_HIDIOCGRDESCSIZE")
    .allowlist_var("_HIDIOCGRDESC")
    .allowlist_var("_ADDITIONAL_CONSTANT")               // Additional constants
    .generate()
    .expect("Unable to get bindings");
```
